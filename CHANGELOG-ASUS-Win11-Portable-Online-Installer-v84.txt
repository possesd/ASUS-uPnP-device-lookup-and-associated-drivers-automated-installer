ROG Strix SCAR 16 G635LW - Windows 11 25H2 Installer v33

v33 change: single one-time hardware/driver/software baseline per script invocation.

1. PnP detection
   - The unbounded pnputil /scan-devices operation now runs exactly once, at the start of each script invocation.
   - There are no later /scan-devices calls anywhere in the package, manufacturer, Windows Update, or final verification phases.
   - The initial scan has no timeout and is allowed to complete fully.

2. Hardware / driver / software inventory
   - Hardware IDs are captured once immediately after the initial PnP scan.
   - Installed driver versions are captured once.
   - Installed software versions/registry entries are captured once.
   - These STAGE 06 snapshots are the only local hardware/driver/software inventory used during that invocation.
   - Final report driver CSV uses the original STAGE 06 driver snapshot rather than querying Win32_PnPSignedDriver again.
   - Manufacturer fallback Intel verification also uses the original snapshot rather than re-querying installed drivers.

3. Package/update phases
   - ASUS package installation, manufacturer fallback installation, and Windows Update retain the original STAGE 06 baseline.
   - Post-install PnP and installed-state refreshes were removed.
   - Persistent package resume state, install ledger, downloaded archives, and reboot checkpoints remain in use.

4. Reboots / resume
   - On an actual reboot, the scheduled AtStartup resume task launches v33 again.
   - That new invocation performs exactly one fresh unbounded PnP scan and one fresh baseline, then resumes from persistent state.
   - Thus there is one baseline per boot/script invocation, not repeated detection throughout the same run.

Note: because v33 intentionally does not re-read installed driver/software state after an installation, decisions during a single invocation are based on the initial baseline plus the persistent package checkpoint/ledger and package ordering. A reboot creates a new baseline.

ROG-G635LW Windows 11 25H2 Driver & Software Installer v34

v34 fixes the Microsoft Store / WinGet error observed on a fresh Windows 11 25H2 installation:

  0x8A15005E : The server certificate did not match any of the expected values.

Observed in v33 during STAGE 07A while installing MyASUS (Microsoft Store package ID 9N7R5S6B0ZZH).

Changes:
- Added Invoke-WingetMsStoreInstall, a common helper for Microsoft Store installs used by MyASUS and the Intel Graphics Command Center companion package.
- A normal Microsoft Store installation is attempted first.
- If WinGet returns 0x8A15005E, v34 temporarily enables the WinGet administrator setting BypassCertificatePinningForMicrosoftStore and retries the same Store operation once.
- The certificate-pinning bypass is restored immediately after the retry; it is NOT left enabled by the installer when v34 started with it disabled.
- The helper checks `winget --info` so that an already-enabled certificate-pinning bypass is not unnecessarily disabled afterward.
- The MyASUS pre-install `winget list --source msstore` query was removed. On the affected fresh installation that query can itself hit the same certificate-pinning failure before the actual install is attempted.
- MyASUS remains non-blocking: if the Store operation cannot be completed, ASUS full packages and Windows Update continue.
- The Intel Graphics Command Center Microsoft Store companion package uses the same certificate-pinning retry helper.
- No changes were made to the v33 one-time PnP detection rule: exactly one unbounded `pnputil /scan-devices` occurs per script invocation, followed by exactly one authoritative hardware/driver/software baseline. A new baseline occurs only when a new script invocation starts, including an automatic post-reboot resume.
- No BIOS/firmware is automatically flashed.

Security note:
Microsoft documents certificate pinning as an additional security control for the Microsoft Store source. The temporary bypass is used only after the specific 0x8A15005E failure and is restored immediately afterward. A persistent bypass is not recommended.

ROG G635LW Windows 11 25H2 Installer v35
==========================================

v35 is based on v34 and addresses the ASUS catalog discovery failure seen after
reboot on fresh Windows 11 installations.

Observed v34 issue:
- ASUS catalog discovery failed immediately with:
  "The remote name could not be resolved: 'rog.asus.com'"
  and the same DNS failure for www.asus.com.
- This is a DNS/network readiness failure, not an ASUS package-selection or
  hardware-association failure.

v35 changes:

   querying the ASUS catalog.
2. The readiness check retries for up to 5 minutes and checks both:
   - rog.asus.com
   - www.asus.com
3. DNS client cache is cleared between failed readiness attempts.
4. Each ASUS catalog endpoint is retried up to 3 times with a short delay and
   DNS-cache refresh between attempts.
5. If the ASUS response is still unavailable, the function exits cleanly without
   advancing the ASUS package checkpoint, so the persistent archive/resume state
   remains intact for the next v35 invocation.
6. Added a null-response guard before JSON parsing so a failed catalog request
   cannot produce a secondary null-response parsing exception.
7. Corrected stale v26/v33 user-facing branding in the current v35 script.
8. The v33/v34 one-time-per-invocation PnP baseline remains unchanged:
   exactly one unbounded PnP rescan and one authoritative hardware/driver/software
   inventory per script invocation. A reboot creates a new invocation and therefore
   a new baseline.
9. v34's Microsoft Store certificate-pinning retry remains included.
10. Reboot Y/N deferral and automatic post-reboot resume remain included.

No BIOS or firmware flashing is added.

v36 is based on v35 and fixes the Microsoft Store problem observed on a fresh Windows 11 installation.

Microsoft Store repair/readiness
--------------------------------
- Before MyASUS or Intel Graphics Command Center is installed, v36 checks Microsoft.WindowsStore.

- Store preparation runs at most once per script invocation.
- If the automatic reboot-resume invocation is running as SYSTEM, Store application work is not attempted under SYSTEM because Store apps require an interactive user context.

WinGet certificate handling
---------------------------
- Retains the v35 temporary BypassCertificatePinningForMicrosoftStore retry for 0x8A15005E.
- The certificate-pinning bypass is temporary and is restored after the Store operation.

ASUS catalog/network handling

One-time hardware baseline
--------------------------
- Retains the v33/v35 behavior: exactly one unbounded PnP rescan per script invocation.
- Exactly one authoritative hardware/driver/software baseline is captured after that rescan.
- No later PnP rescan or hardware/driver/software inventory refresh occurs during the same invocation.
- A new automatic post-reboot invocation receives one new baseline.

Resume/reboot
-------------
- Retains automatic startup resume and persistent package checkpoints.
- Reboot-deferred package state remains resumable without redownloading valid archived files.

Version/branding
----------------
- Corrected internal Version, ProgramData state directory, stable resume script name, scheduled task name, user-facing reset text, and final report branding to v36.

ROG-G635LW Windows 11 25H2 Installer v39

Fixes in v39

1. FIXED AUTOMATIC REBOOT RESUME FAILURE
   v38 used:
       Split-Path -LiteralPath $StableScript -Parent
   PowerShell does not permit -LiteralPath and -Parent in the same Split-Path
   parameter set. Microsoft documents -LiteralPath as its own parameter set,
   while -Parent belongs to the normal -Path/Parent set.

   v39 now uses:
       [IO.Path]::GetDirectoryName($StableScript)
   This removes the parameter-set ambiguity completely.

2. STARTUP RESUME FALLBACK
   If the persistent stable-copy refresh ever fails for another filesystem reason,
   v39 registers the currently running script itself as the startup-resume fallback
   instead of aborting before the scheduled resume task can be registered.

3. AUTOMATIC REBOOT RESUME REMAINS ENABLED
   The resume task is registered before the reboot and launches automatically at
   Windows startup with the -Resume switch.

4. NEW RESUME TASK NAME
   ROG-G635LW-Installer-v39-Resume

5. ONE-TIME HARDWARE BASELINE RETAINED
   The no-timeout PnP scan and authoritative hardware/driver/software baseline
   still occur only once per script invocation. A reboot creates a new invocation
   and therefore one new baseline, as designed.

No BIOS/firmware flashing behavior was added.
